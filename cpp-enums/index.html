02. The Investigation

ANALYSIS: ASSEMBLY & LIBSTDC++ SOURCE

[A] WHY CHAR WINS IO (3.5x)

It is NOT about size. It is about Function Overloading.

INT PATH
call operator<<(int)
  • Sign Check
  • Integer Division (expensive)
  • Modulo 10
  • ASCII Conversion
CHAR PATH
call operator<<(char)
  • Buffer Check
  • MOV Byte
  • DONE

[B] WHY CHAR LOSES PURE MOVE (-O0)

The "Natural Width" Penalty. CPU prefers 32/64-bit.

INT ASM (CLEAN):
movl $1, -8(%rbp)    # Store 32-bit
movl -8(%rbp), %eax  # Load 32-bit
CHAR ASM (DIRTY):
movb $83, -9(%rbp)   # Store 8-bit
movsbl -9(%rbp), %eax # PENALTY! Sign-Extend
MOVSBL (Move with Sign-Extend Byte to Long) is required to safely promote 8-bit to 32-bit register for operations.

[C] WHY CHAR WINS PURE MOVE (-O3)

Memory Bandwidth Axiom.

INT WRITE4 BYTES per op
CHAR WRITE1 BYTE per op
CACHE PRESS.CHAR = 25% OF INT
