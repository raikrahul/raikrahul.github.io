02. The Investigation

ANALYSIS: ASSEMBLY, PIPELINE, & STACK SPILLS

[A] THE CMOV vs BRANCH AXIOM

Axiom: x86-64 has `cmovne` for 32-bit/64-bit registers, but NO conditional move for 8-bit registers.

INT (32-bit)
cmovne %ecx, %eax
> Single Instruction
> No Branch
> No Pipeline Flush
CHAR (8-bit)
jne .LBB4_6
> BRANCH REQUIRED
> Misprediction Risk
> Pipeline Stalls

[B] STACK SPILL PROOF (-O0)

The compiler runs out of generic registers for 8-bit ops, forcing stack use.

INT ASM (Registers Only):
movl $1, -8(%rbp)   # 1 op (store)
movl -8(%rbp), %eax # 1 op (load)
CHAR ASM (Stack Thrashing):
movb %dl, -42(%rbp) # Spill BUY to stack
movb %al, -41(%rbp) # Spill SELL to stack
...                 # Branch Logic
movb -41(%rbp), %al # Reload from stack
> 4 Stack Ops vs 2 Stack Ops
> Unaligned byte access on stack

[C] THE SIGN-EXTENSION PENALTY

movsbl -9(%rbp), %eax  # Move with Sign-Extend Byte to Long
  • Fact: CPU ALUs operate on native width (32/64 bit).
  • Cost: 8-bit values must be promoted (sign-extended) to be useful.
  • Result: Extra instruction latency for every single load.

[D] CONCLUSION

1. IO: `char` wins (Function Overloading).
2. Bandwidth: `char` wins (-O3, 1 vs 4 bytes).
3. Pipeline: `int` wins (-O0, `cmov` vs `branch` + spills).
